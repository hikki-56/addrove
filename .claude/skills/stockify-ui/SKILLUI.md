# Clean Green UI — ระบบสามสี 60 / 30 / 10

ระบบนี้มีเป้าหมายเดียว คือทำให้หน้าจอ **อ่านง่ายในหนึ่งวินาที** โดยใช้สีแค่สามตัว
ข้อจำกัดเรื่องสีไม่ใช่การลดทอน แต่เป็นสิ่งที่บังคับให้ลำดับความสำคัญของข้อมูลชัดขึ้น
เมื่อมีสีเดียวที่ใช้เน้นได้ สิ่งที่ถูกเน้นจึงมีความหมายจริง

---

## 1. อ่านสัดส่วน 60/30/10 ให้ถูก

สัดส่วนนี้วัดจาก **พื้นที่บนหน้าจอ** ไม่ใช่จำนวนชิ้นงาน นี่คือจุดที่คนเข้าใจผิดบ่อยที่สุด

| สี | สัดส่วน | ใช้กับอะไร |
|---|---|---|
| **ขาว** | ~60% | พื้นหลังหน้า พื้นการ์ด พื้นตาราง ช่องว่างระหว่างองค์ประกอบ |
| **เขียว** | ~30% | แถบหัวเรื่อง ปุ่มหลัก แท่งกราฟ เมนูที่กำลังใช้งาน ไอคอนนำสายตา เส้นเน้น |
| **ดำ** | ~10% | ตัวอักษร ตัวเลขสำคัญ เส้นขอบบาง ไอคอนทั่วไป |

ตัวอักษรกินพื้นที่จริงน้อยมาก แม้จะเป็นสีดำทั้งหน้า ก็ยังไม่เกิน 10%
ถ้ารู้สึกว่าหน้ามืดเกินไป มักไม่ใช่เพราะตัวอักษร แต่เพราะมีบล็อกพื้นเข้มหรือเส้นขอบหนาเกินจำเป็น

**วิธีตรวจเร็ว** — หรี่ตามองหน้าจอ ควรเห็นพื้นขาวเป็นหลัก มีเขียวเป็นก้อนใหญ่ 1–2 จุดที่นำสายตา
ถ้าเห็นเขียวกระจายเป็นจุดเล็กๆ ทั่วหน้า แปลว่ากระจายเกินไป ให้รวบเขียวไปไว้ที่จุดสำคัญจุดเดียว

## 2. โทเคนสี

วางไว้ที่ `:root` แล้วเรียกใช้ผ่านตัวแปรเสมอ อย่าฮาร์ดโค้ดค่าสีลงในคอมโพเนนต์
เมื่อลูกค้าขอเปลี่ยนเฉดเขียว จะแก้ที่เดียวจบ

```css
:root {
  /* ── ขาว (60%) ── */
  --w-0:  #FFFFFF;   /* พื้นการ์ด พื้นตาราง */
  --w-1:  #F7F9F8;   /* พื้นหน้า พื้นแถวสลับ พื้นช่องกรอก */

  /* ── เขียว (30%) ── */
  --g-50:  #F1F7F4;  /* พื้นอ่อนมาก ใช้เน้นแถวหรือกล่องแจ้งเตือน */
  --g-100: #DEEDE6;  /* พื้นป้ายสถานะ */
  --g-200: #B9DACB;  /* เส้นขอบเน้น */
  --g-300: #8AC2AB;  /* กราฟลำดับรอง */
  --g-400: #55A587;  /* กราฟลำดับรอง */
  --g-500: #2E8B6B;  /* สีหลักของแบรนด์ ใช้กับพื้นที่ใหญ่และแท่งกราฟ */
  --g-600: #1F6E54;  /* ปุ่มหลัก ลิงก์ ตัวอักษรบนพื้นขาว */
  --g-700: #17563F;  /* สถานะ hover ของปุ่ม */
  --g-800: #113F2F;  /* แถบหัวเรื่องเข้ม */

  /* ── ดำ (10%) ── */
  --k-900: #101614;  /* หัวเรื่อง ตัวเลขสำคัญ */
  --k-700: #37413D;  /* เนื้อความ */
  --k-500: #6B7671;  /* ข้อความรอง คำอธิบายใต้ฟิลด์ */
  --k-300: #A7AFAB;  /* ข้อความจาง placeholder */
  --k-200: #D9DEDB;  /* เส้นขอบ เส้นคั่นตาราง */

  --radius: 14px;
  --shadow: 0 1px 2px rgba(16,22,20,.04), 0 8px 24px -14px rgba(16,22,20,.16);
}
```

### กฎคอนทราสต์ที่ห้ามพลาด

ค่าเหล่านี้ผ่านการคำนวณมาแล้ว ใช้ตามนี้จะผ่านมาตรฐาน WCAG AA เสมอ

- **ตัวอักษรขาวบนพื้นเขียว** → พื้นต้องเป็น `--g-600` ขึ้นไป (อัตราส่วน 6.2:1)
  `--g-500` กับตัวอักษรขาวได้แค่ 4.2:1 **ใช้ได้เฉพาะตัวอักษรใหญ่ 24px ขึ้นไป หรือ 19px ตัวหนา**
- **ตัวอักษรเขียวบนพื้นขาว** → ใช้ `--g-600` ขึ้นไป ห้ามใช้ `--g-500` กับตัวอักษรขนาดปกติ
- **เนื้อความ** → `--k-700` บนพื้นขาว ห้ามใช้ `--k-500` กับเนื้อความหลัก มันจางเกินไปสำหรับการอ่านนานๆ
- **เส้นคั่นตาราง** → `--k-200` เท่านั้น เส้นเข้มกว่านี้จะทำให้ตารางดูเหมือนกรง

## 3. ตัวอักษร

เลือกคู่ฟอนต์ให้ทำหน้าที่ต่างกันชัดเจน อย่าใช้ฟอนต์เดียวทั้งหน้าแล้วหวังว่าน้ำหนักตัวอักษรจะช่วย

**สำหรับงานภาษาไทย** (ค่าเริ่มต้นที่แนะนำ)

```css
@import url("https://fonts.googleapis.com/css2?family=Anuphan:wght@400;500;600;700&family=IBM+Plex+Sans+Thai:wght@400;500;600&family=IBM+Plex+Mono:wght@400;500&display=swap");
```

| บทบาท | ฟอนต์ | ใช้กับ |
|---|---|---|
| หัวเรื่อง / ตัวเลขเด่น | Anuphan 600 | ชื่อหน้า ชื่อการ์ด ยอดรวม ตัวเลขสถิติ |
| เนื้อความ | IBM Plex Sans Thai 400–500 | ย่อหน้า ป้ายกำกับ เนื้อตาราง |
| รหัส / ตัวเลขที่ต้องเรียงหลัก | IBM Plex Mono 400 | เลขที่เอกสาร รหัสสินค้า เลขบัญชี วันที่ |

ทางเลือกอื่นที่ใช้ได้ดี — Noto Sans Thai (ทางการ), Sarabun (เอกสารราชการ), Mitr (เป็นกันเอง)
หลีกเลี่ยงฟอนต์เหลี่ยมจัดอย่าง Chakra Petch หรือ Bai Jamjuree กับงานที่ต้องนั่งดูทั้งวัน มันทำให้หน้าจอดูแข็งและล้าตา

**ตัวเลขในตารางและกราฟ** ให้ใส่ `font-variant-numeric: tabular-nums;` เสมอ
ถ้าไม่ใส่ ตัวเลขจะขยับซ้ายขวาตอนอัปเดต และหลักจะไม่ตรงกันเมื่อเทียบระหว่างแถว

**ขนาดที่ใช้ได้จริง** — 12px (ป้ายกำกับเล็ก), 13–14px (เนื้อความ, ตาราง), 19px (ชื่อการ์ด), 28px (ตัวเลขสถิติ), 44–58px (ยอดรวมหลักของหน้า)
`line-height: 1.6` สำหรับเนื้อความไทย เพราะสระบนล่างต้องการที่หายใจมากกว่าภาษาอังกฤษ

## 4. สูตรคอมโพเนนต์

### ปุ่ม

```css
.btn-primary {                      /* ใช้ได้ปุ่มเดียวต่อหนึ่งบล็อก */
  background: var(--g-600); color: #fff;
  padding: 12px 22px; border-radius: 999px;
  font-weight: 600; border: none;
}
.btn-primary:hover { background: var(--g-700); }

.btn-secondary {
  background: var(--w-0); color: var(--g-600);
  border: 1px solid var(--g-200);
  padding: 11px 21px; border-radius: 999px; font-weight: 600;
}

.btn-ghost { background: none; color: var(--k-700); border: none; }
```

หนึ่งหน้าจอควรมีปุ่มเขียวทึบ **หนึ่งปุ่ม** ถ้ามีสองปุ่มเขียวคู่กัน ผู้ใช้จะลังเลว่าควรกดอันไหน
ปุ่มรองใช้เส้นขอบ ปุ่มลำดับสามใช้ตัวอักษรเปล่า

### การ์ด

```css
.card {
  background: var(--w-0);
  border: 1px solid var(--k-200);
  border-radius: var(--radius);
  box-shadow: var(--shadow);
  padding: 26px;
}
```

ใช้ทั้งเส้นขอบและเงาพร้อมกันได้ แต่ต้องบางทั้งคู่ เงาช่วยให้การ์ดดูลอย เส้นขอบช่วยให้ขอบชัดตอนพิมพ์ออกกระดาษ
ถ้าการ์ดซ้อนในการ์ด ให้ชั้นในใช้พื้น `--w-1` และไม่ต้องมีเงา

### ป้ายสถานะ

```css
.badge { padding: 5px 12px; border-radius: 999px; font-size: 12px; font-weight: 500; }
.badge-ok      { background: var(--g-100); color: var(--g-700); }
.badge-neutral { background: var(--w-1);   color: var(--k-500); }
```

### ตาราง

- หัวตาราง — `--k-500` ขนาด 12px ไม่ต้องหนา ไม่ต้องพื้นสีเทา
- เส้นคั่นเฉพาะระหว่างแถว (`border-top`) ไม่ต้องมีเส้นตั้ง
- Hover ทั้งแถวเป็น `--w-1` พร้อมมุมมนที่หัวและท้ายแถว ช่วยให้กวาดสายตาตามแนวนอนได้
- ตัวเลขชิดขวาเสมอ ข้อความชิดซ้ายเสมอ
- คอลัมน์รหัสใช้ฟอนต์ mono ให้หลักตรงกัน

### ฟอร์ม

```css
.input {
  background: var(--w-1); border: 1px solid var(--k-200);
  border-radius: 10px; padding: 11px 14px; font-size: 14px;
}
.input:focus {
  outline: none; background: var(--w-0);
  border-color: var(--g-500);
  box-shadow: 0 0 0 3px var(--g-50);
}
```

ป้ายกำกับอยู่**เหนือ**ช่องกรอกเสมอ ไม่ใช่ด้านซ้าย เพราะบนมือถือฟอร์มแบบซ้าย-ขวาจะพัง
ข้อความอธิบายใต้ฟิลด์ใช้ `--k-500` ขนาด 12px

### กราฟ

มีสีเดียวใช้ จึงต้องไล่เฉดเป็นระบบ

- **กราฟเปรียบเทียบหมวดหมู่** — ไล่ `--g-500` → `--g-300` ตามลำดับค่ามากไปน้อย เฉดเข้มคือค่ามาก ซึ่งเป็นการเข้ารหัสข้อมูลจริง ไม่ใช่การตกแต่ง
- **กราฟเส้นหลายเส้น** — เส้นสำคัญที่สุดใช้ `--g-600` เส้นอื่นใช้ `--k-300` อย่าให้ทุกเส้นเด่นเท่ากัน
- **เส้นตาราง** — `--k-200` แบบประ ตัดเส้นตั้งออก
- **แกน** — ตัวอักษร `--k-500` ไม่ต้องมีเส้นแกน
- ใส่ตัวเลขจริงบนหัวแท่งไปเลยถ้ามีไม่เกิน 8 แท่ง ผู้ใช้จะได้ไม่ต้องกวาดตาไปหาแกน

## 5. ระยะห่างและโครงหน้า

ใช้สเกลระยะแบบ 4px — 4, 8, 12, 16, 22, 26, 32, 48 เลือกจากสเกลนี้เท่านั้น
ค่าที่หลุดสเกลอย่าง 15px หรือ 23px จะทำให้หน้าดูไม่เรียบร้อยแบบที่บอกไม่ถูก

- ระยะระหว่างการ์ด 22px
- ระยะขอบในการ์ด 26px
- ระยะระหว่างส่วนใหญ่ของหน้า 32px
- ความกว้างสูงสุดของเนื้อหา 1180px แล้วจัดกลาง

**ลำดับสายตา** — บนสุดของหน้าคือคำตอบของคำถามที่ผู้ใช้เปิดหน้านี้มาถาม
ถ้าเป็นแดชบอร์ดคือตัวเลขสรุปที่สำคัญที่สุด ถ้าเป็นฟอร์มคือสิ่งที่ต้องกรอก
อย่าเริ่มหน้าด้วยแถบเครื่องมือหรือตัวกรอง สิ่งเหล่านั้นเป็นเครื่องมือ ไม่ใช่คำตอบ

## 6. เมื่อจำเป็นต้องใช้สีที่สี่

ระบบสามสีมีข้อจำกัดจริงข้อเดียว คือ**การเตือนภัย** สีเขียวสื่อว่า "ปกติ" อยู่แล้ว จึงใช้เตือนไม่ได้

อนุญาตให้เพิ่มสองสีนี้ได้ ภายใต้เงื่อนไขว่ารวมกันต้องไม่เกิน **2% ของพื้นที่หน้าจอ**
ใช้ได้เฉพาะกับจุด ป้ายเล็ก และตัวเลขที่ต้องเตือน ห้ามใช้เป็นพื้นบล็อกใหญ่หรือปุ่ม

```css
--warn: #B57B33;   /* รอดำเนินการ ใกล้ครบกำหนด ใกล้หมด */
--warn-bg: #FBF0E2;
--danger: #A34A37; /* ยกเลิก ผิดพลาด เกินกำหนด */
--danger-bg: #FAEAE6;
```

สีสองตัวนี้ถูกลดความสดลงมาให้อยู่ในโลกเดียวกับเขียว ถ้าใช้แดงสดหรือส้มสด มันจะกระโดดออกจากระบบทันที

**ห้ามเพิ่มสีเพื่อความสวยงามหรือเพื่อแยกหมวดหมู่** ถ้าต้องแยกหมวดหมู่ ให้ใช้เฉดเขียวไล่ระดับ หรือใช้ตำแหน่งและป้ายกำกับแทน
กราฟหกสีรุ้งคือสัญญาณว่าคนออกแบบยอมแพ้ในการจัดลำดับความสำคัญ

## 7. ตรวจก่อนส่งงาน

- [ ] หรี่ตามองแล้วเห็นขาวเป็นหลัก เขียวรวมเป็นก้อนใหญ่ 1–2 จุด
- [ ] มีปุ่มเขียวทึบไม่เกินหนึ่งปุ่มต่อหนึ่งบล็อก
- [ ] ตัวอักษรขาวไม่ได้วางบนพื้น `--g-500` ในขนาดปกติ
- [ ] เนื้อความใช้ `--k-700` ไม่ใช่สีจางกว่านั้น
- [ ] ตัวเลขทุกที่ใช้ `tabular-nums` และชิดขวา
- [ ] ระยะห่างทุกค่าหลุดมาจากสเกล 4px
- [ ] กด Tab แล้วเห็นกรอบโฟกัสชัดเจนทุกจุดที่กดได้
- [ ] ย่อจอเหลือ 380px แล้วยังใช้งานได้ ตารางเลื่อนแนวนอนได้ ฟอร์มไม่ล้น
- [ ] ไม่มีสีที่ห้าโผล่มา ไม่มีไล่เฉดรุ้ง ไม่มีอิโมจิแทนไอคอน
- [ ] สถานะว่างเปล่า (ไม่มีข้อมูล) ถูกออกแบบไว้แล้ว พร้อมทางไปต่อ

## 8. ตัวอย่างการเรียบเรียงหน้า

**แดชบอร์ด** — แถบหัวเรื่องเขียวเข้มเต็มความกว้างพร้อมยอดรวมตัวใหญ่สีขาว (นี่คือก้อนเขียว 30% ของหน้า) จากนั้นทุกอย่างใต้ลงมาเป็นการ์ดขาวบนพื้น `--w-1` กราฟใช้เฉดเขียว ปุ่มหลักหนึ่งปุ่มที่มุมของแผงงานค้าง

**หน้ารายการ / ตาราง** — หัวเรื่องดำบนพื้นขาว แถบกรองเป็นพื้น `--w-1` ตารางขาวล้วน แถวที่ถูกเลือกเป็น `--g-50` ปุ่ม "เพิ่มรายการ" เขียวทึบที่มุมขวาบนปุ่มเดียว

**ฟอร์ม** — พื้น `--w-1` การ์ดขาวกลางจอกว้างไม่เกิน 680px ป้ายกำกับดำ ช่องกรอกพื้น `--w-1` ขอบโฟกัสเขียว ปุ่มบันทึกเขียวทึบ ปุ่มยกเลิกเป็นตัวอักษรเปล่า

**รายงานสำหรับพิมพ์** — ตัดเงาออกทั้งหมด เหลือเส้นขอบบาง เปลี่ยนแถบหัวเรื่องเขียวทึบเป็นเส้นเขียวหนา 4px ใต้ชื่อรายงาน เพราะพื้นเข้มเต็มหน้ากินหมึกและอ่านยากบนกระดาษ
