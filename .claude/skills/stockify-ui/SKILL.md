# Stockify UI

## ใครใช้แอปนี้ (ที่มาของกติกาทุกข้อ)

พนักงานคลังสินค้าคนไทย ยืนอยู่หน้าชั้นวาง **ถือมือถือด้วยมือเดียว** อีกมือถือของหรือเครื่องสแกน
งานหลักคือสแกนบาร์โค้ด กรอกจำนวน กดยืนยัน แล้วเดินต่อ ไม่ได้นั่งหน้าจอ 27 นิ้วในออฟฟิศ

ทุกกติกาข้างล่างมาจากข้อนี้ ถ้าเจอกรณีที่สกิลไม่ได้ครอบคลุม ให้ย้อนกลับมาถามตัวเองว่า
"คนที่ถือมือถือมือเดียวในคลังจะใช้ได้ไหม" แล้วตอบจากตรงนั้น

ตัวเลขในระบบนี้คือของจริงในคลัง — กรอกผิดหลักเดียวคือของหาย ความชัดเจนจึงสำคัญกว่าความสวย

---

## กติกา 6 ข้อ

### 1. Mobile-first ผ่าน `sm:` เท่านั้น

คลาสเปล่า = มือถือ, `sm:` = จอใหญ่ ในโปรเจคนี้ `sm:` ถูกใช้ 598 จุด ส่วน `md:` 35 และ `lg:` 34
แปลว่ามี breakpoint ที่ใช้งานจริงแค่จุดเดียว **อย่าเผลอเอื้อมไปใช้ `md:`/`lg:` ตามความเคยชิน**
เพราะจะได้เลย์เอาต์ที่ไม่มีใครในโปรเจคนี้เห็นตอนเทส

```tsx
// ถูก — ฐานคือมือถือ แล้วขยายที่ sm:
<div className="grid grid-cols-1 sm:grid-cols-2 gap-3">
<button className="w-full py-3 sm:py-3.5 text-xs sm:text-sm">

// ผิด — ฐานคือเดสก์ท็อปแล้วค่อยบีบลง / ใช้ breakpoint ที่โปรเจคไม่ใช้
<div className="grid grid-cols-3 md:grid-cols-1">
```

เป้าที่นิ้วโป้งกดต้องสูงอย่างน้อย `py-2.5` (~40px) ปุ่มยืนยันหลักใช้ `py-3` ขึ้นไป

### 2. `globals.css` ไม่ใช่แหล่งความจริง — อย่าลอกจากมัน

ไฟล์นี้ 681 บรรทัด นิยาม design token ไว้สวยงาม แต่ `var(--...)` **ถูกใช้ในไฟล์ .tsx เป็นศูนย์จุด**
ขณะที่คลาสสี Tailwind ถูกใช้ 3,007 จุด กล่าวคือระบบที่เขียนไว้กับระบบที่ใช้จริงเป็นคนละอัน

แย่กว่านั้น มันคือ **ธีมมืดที่ถูกทาสีขาวทับ** ของที่ยังหลงเหลือ:
- `.glass-card` มีเงาดำ `rgba(0,0,0,0.4)` ที่ออกแบบมาสำหรับพื้นหลังมืด
- scrollbar thumb เป็น `rgba(255,255,255,0.12)` = ขาวบนขาว มองไม่เห็น
- แถวตารางคู่เป็น `rgba(255,255,255,0.02)` = ไม่มีผลบนพื้นขาว
- มี `html.light ... !important` 80 จุด คอยลบล้างคลาสมืดที่ฮาร์ดโค้ดไว้ในหน้าเว็บ
- คลาสหลายตัวตายสนิท ไม่มีใครเรียก: `.admin-button-primary`, `.admin-button-secondary`,
  `.admin-tab`, `.admin-text-link`, `.badge-low`, `.badge-negative`

**เขียน UI ใหม่ด้วย Tailwind utility ตาม `references/patterns.md`** อย่าเพิ่มคลาสใหม่ลง globals.css
และอย่าใช้ token — ทิศทางของโปรเจคคือ utility ชนะไปแล้ว การเพิ่มของลงชั้นที่ตายแล้ว
มีแต่จะทำให้คนถัดไปสับสนหนักขึ้น

### 3. ระวังเศษธีมมืดในไฟล์ .tsx

การลอกสไตล์จากไฟล์ข้าง ๆ เป็นวิธีที่ดี **ยกเว้น** เมื่อบังเอิญลอกโดนของเก่า ยังมี input ธีมมืดตกค้าง
อยู่ 9 จุดใน 2 ไฟล์ (`ScanFeedbackBanner.tsx`, `products/[id]/page.tsx`) หน้าตาแบบนี้:

```tsx
// เศษธีมมืด — ตัวหนังสือขาวบนพื้นขาว ผู้ใช้มองไม่เห็นสิ่งที่ตัวเองพิมพ์
className="bg-white/5 border border-emerald-900/30 text-white placeholder-gray-500"
```

สัญญาณอันตราย: `bg-white/5`, `bg-black/…`, `text-white` บนช่องกรอก, `border-*-900/…`,
`text-gray-300`/`text-slate-300` เป็นสีตัวอักษรหลัก, หรือสีฮาร์ดโค้ดอย่าง `bg-[#0a0a0f]`
เจอเมื่อไหร่ให้แทนด้วยของจริงจาก `references/patterns.md`

### 4. ใช้ component ที่มีอยู่แล้ว

มีของพร้อมใช้อยู่ การเขียนใหม่ทำให้พฤติกรรมสแกนเนอร์แตกกัน ซึ่งพนักงานจะเจอทันที

| ต้องการ | ใช้ตัวนี้ |
|---|---|
| ช่องสแกนบาร์โค้ด (ยิงแล้ว submit เอง) | `@/components/scanner/BarcodeScanInput` |
| แจ้งผลการสแกน สำเร็จ/ล้มเหลว | `@/components/scanner/ScanFeedbackBanner` |
| สแกนด้วยกล้องมือถือ | `@/components/ui/CameraBarcodeScannerModal` |
| แสดงบาร์โค้ด (กดขยายได้) | `@/components/ui/BarcodeSvg` |
| ค้นหาสินค้าแบบพิมพ์แล้วกรอง | `@/components/ui/ProductSearchInput` |
| dropdown ทั่วไป | `@/components/ui/CustomSelect` |
| เลือกค่าแบบเลื่อนด้วยนิ้ว (เหมาะกับรายการยาว) | `@/components/ui/ScrollSelect` |
| แท็บสลับโกดัง | `@/components/warehouse/WarehouseTabs` |

**ไอคอน: ใช้ inline `<svg>`** โปรเจคนี้มีไอคอน inline 244 จุด และ **ไม่มี icon library เป็น
dependency เลย** อย่าติดตั้ง lucide-react หรือ heroicons เพิ่มโดยไม่ถาม — มันเพิ่ม bundle
ให้ผู้ใช้ที่ต่อเน็ตมือถือในคลัง เพื่อแลกกับสิ่งที่ copy-paste 20 บรรทัดก็ได้แล้ว

### 5. ตัวเลขและรหัสต้องอ่านผิดไม่ได้

- จำนวนที่แสดงผลใช้ `toLocaleString()` เสมอ — `50,000` ไม่ใช่ `50000` (ใช้อยู่ 64 จุด)
- SKU / บาร์โค้ด / เลขที่เอกสาร ใส่ `font-mono` เพื่อให้ `0` กับ `O`, `1` กับ `l` แยกออก
- **บาร์โค้ดคือ string เสมอ ห้ามแปลงเป็น number** เคยมีบั๊กที่บาร์โค้ด 13 หลักถูกตัดเหลือ 8 หลัก
  ให้ผ่าน `to8DigitBarcode()` ใน `@/lib/barcode-utils` (ชื่อฟังก์ชันหลอก — ปัจจุบันมันคืนค่าเดิม
  ไม่ตัดหลัก และกรองค่าขยะอย่าง `-`, `trf-*` ให้ด้วย)
- ตัวเลขที่ผู้ใช้ต้องอ่านเร็ว ๆ ใช้ `font-bold` ขึ้นไป ระบบนี้ใช้ `font-bold` 502 จุดและ
  `font-black` 115 จุด — น้ำหนักตัวอักษรคือวิธีจัดลำดับความสำคัญหลักของแอปนี้

### 6. ข้อความภาษาไทย เขียนแบบสั่งงาน ไม่ใช่แบบราชการ

ข้อความ validation ขึ้นต้นด้วย "กรุณา" + สิ่งที่ต้องทำ สั้น ตรง ไม่ใช้ "ท่าน"

```
กรุณาเลือกสินค้าที่ต้องการย้าย
กรุณาเลือกคลังต้นทางและคลังปลายทาง
คลังต้นทางและคลังปลายทางต้องไม่ซ้ำกัน
จำนวนต้องมากกว่า 0
PIN ผิดเกิน 5 ครั้ง — ล็อค 5 นาที
```

บอกด้วยว่า**ต้องทำอะไรต่อ** ไม่ใช่แค่บอกว่าพัง ใช้ `—` (em dash) คั่นเหตุกับผล
ศัพท์เทคนิคที่ไม่มีคำไทยที่คนใช้จริง (PIN, QR, Express, SKU) เขียนทับศัพท์ได้เลย

## สีมีความหมาย อย่าสลับ

| สี | หมายถึง | ใช้กับ |
|---|---|---|
| **indigo** | การกระทำหลัก | ปุ่มยืนยัน, ลิงก์, เมนูที่เลือกอยู่, focus ring |
| **emerald** | สต็อก / สำเร็จ | ยอดคงเหลือปกติ, ผลสแกนสำเร็จ, ปุ่มบันทึกในหน้ารับของ |
| **rose** | ทำลาย / ปฏิเสธ | ยกเลิกใบงาน, ลบ, ปฏิเสธการอนุมัติ |
| **amber** | เตือน | สต็อกต่ำกว่าขั้นต่ำ, รออนุมัติ |
| **slate** | โครงสร้าง | ตัวอักษร, เส้นขอบ, พื้นหลังช่องกรอก |

ปุ่มที่ทำลายของต้องเป็น rose เสมอ — พนักงานจำสีได้เร็วกว่าอ่านข้อความ และหน้าจอนี้ถูกกด
ขณะเดินอยู่ ปุ่มยกเลิกสีเทาปนกับปุ่มอื่นคือความเสี่ยงที่ของจะหายจริง

## เก็บกวาดเมื่อเจอ (ไม่ต้องตั้งงาน refactor แยก)

ตอนแก้ไฟล์ไหนก็ตาม ถ้าเจอของพวกนี้ในไฟล์นั้น ให้แก้ไปพร้อมกัน แต่ **อย่าไล่แก้ทั้งโปรเจค
ในครั้งเดียว** — diff ใหญ่ ๆ ที่ปนกับงานจริงทำให้รีวิวไม่ได้

แก้ได้เลย ไม่ต้องถาม:
- เศษธีมมืดตามข้อ 3 (ตัวหนังสือขาวบนขาว = บั๊กที่ผู้ใช้เจอจริง)
- คลาสที่ตายแล้วอย่าง `.admin-*`, `.badge-low`, `.badge-negative` → แทนด้วย utility
- จำนวนที่แสดงโดยไม่ผ่าน `toLocaleString()`
- `md:`/`lg:` เดี่ยว ๆ ที่ไม่มี `sm:` คู่กัน → เปลี่ยนเป็น `sm:`

ถามก่อน:
- ลบบล็อก `html.light ... !important` ใน globals.css (ต้องเช็คว่าไม่มีหน้าไหนพึ่งอยู่)
- เปลี่ยน `.glass-card` / `.btn-primary` ที่ยังมีคนใช้อยู่ 15 และ 9 จุด

## สูตรคลาสที่ใช้จริง

`references/patterns.md` มีคลาสพร้อมวางสำหรับ การ์ด, ปุ่มทุกแบบ, ช่องกรอก, ตาราง, modal,
badge สถานะ, empty state, loading, และฟอร์ม อ่านไฟล์นั้นก่อนเขียน markup ใหม่ —
มันสั้น และการเดาเองจะได้สไตล์ที่เพี้ยนจากหน้าอื่นทีละนิด ซึ่งสะสมแล้วกลายเป็นแอปที่ดูไม่เป็นชุดเดียวกัน

## ตรวจก่อนจบงาน

รันตัวตรวจกติกากับไฟล์ที่แก้:

```bash
bash .claude/skills/stockify-ui/evals/check-ui-conventions.sh $(git diff --name-only | grep '\.tsx$')
```

มันจับได้แค่สิ่งที่ grep เห็น (breakpoint, เศษธีมมืด, toLocaleString, dvh, icon library,
คลาสที่ตายแล้ว) — ผ่านครบไม่ได้แปลว่า UI ดี แต่ไม่ผ่านแปลว่ามีของที่ขัดกับหน้าอื่นแน่ ๆ

จากนั้นรัน `npm run lint` แล้วดูว่าไม่ได้เพิ่ม error ใหม่ (ตอนนี้มี error ค้างอยู่ 2 จุดที่
`production/page.tsx` เรื่องเครื่องหมายคำพูดที่ยังไม่ escape — ไม่ใช่ของคุณ แต่ถ้าแก้ไฟล์นั้นอยู่แล้ว
ก็จัดการไปด้วยได้)

ถ้าอยากเห็นของจริงบนหน้าจอ ใช้สกิล `run` เปิดแอปแล้วแคปหน้าจอ — **ย่อหน้าต่างให้แคบระดับมือถือ
ก่อนแคป** เพราะนั่นคือขนาดที่ผู้ใช้จริงเห็น การดูแค่จอกว้างจะพลาดปัญหาที่พนักงานเจอทุกวัน
