## 1. ภาพรวมโจทย์และผู้ใช้

### 1.1 โจทย์

เมนูเบิกสินค้าคือเมนูเดียวในแอปที่ **งานผ่านมือสองคนและมีช่วงเวลาคั่น**: แอดมินสร้างใบที่โต๊ะทำงาน, พนักงานหยิบของทีหลังหลายชั่วโมงโดยยืนอยู่หน้าชั้นวางและอ่านคำสั่งจากมือถือตัวเดียว คำสั่งบนจอต้องสมบูรณ์ในตัวเอง — พนักงานไม่มีแอดมินอยู่ข้าง ๆ ให้ถาม ความเสี่ยงอันดับหนึ่งคือ "หยิบไม่ครบ/หยิบเกินแล้วปิดใบงาน" ตัวเลขจำนวนและรหัสชั้นวางจึงต้องเด่นและอ่านผิดไม่ได้

### 1.2 Persona

**P1 — แอดมิน (ADMIN)**
- ที่ทำงาน: โต๊ะสำนักงาน เปิดทั้งคอมและมือถือ แสงดี ใช้เมาส์/คีย์บอร์ดได้
- งานที่ทำ: สร้างใบเบิกแทนหน่วยงาน, ติดตามว่าใบไหนถึงขั้นไหน, อนุมัติ/ปฏิเสธ/ยกเลิก, ดูประวัติและส่งออก CSV
- ความต้องการ: กรอกหลายรายการต่อใบได้เร็ว, เห็นสถานะ live ของทุกใบ, ยืนยันด้วยค่าจริงก่อนตัดสต็อก

**P2 — พนักงานคลัง (WAREHOUSE_STAFF)**
- ที่ทำงาน: ยืนอยู่ในคลัง แสงไม่สม่ำเสมอ ถือมือถือ**มือเดียว** อีกมือถือของ อาจใส่ถุงมือ อายุ 45-60 สายตายาว บางคนไม่ได้พกแว่น
- งานที่ทำ: เปิดดูคิวงานของโกดังตัวเอง → สแกนบาร์โค้ดสินค้า → ไปวางที่ชั้นปลายทางแล้วสแกนชั้น → ยืนยันส่งอนุมัติ
- ความต้องการ: ตัวหนังสือ/ตัวเลขใหญ่ (ไม่ต่ำกว่าสเกลหัวข้อ 6), ปุ่มโดนง่ายมือเดียว, ขั้นตอนไม่ต้องจำ, ผลสแกนฟ้องทันทีทั้งถูกและผิด, ข้อความผิดพลาดบอกทางออก
- ผลกระทบถ้าออกแบบพลาด: หยิบผิดชิ้น/ผิดชั้น → ยอดสต็อกเพี้ยนจริง

**P3 — ผู้อนุมัติ (APPROVER)**
- ที่ทำงาน: สำนักงาน/เดินตรวจคลัง เปิดมือถือเป็นหลัก
- ข้อจำกัดสิทธิ์: เมนูเบิกสินค้าคือ**เมนูเดียวของทั้งแอป**ที่เห็น (`getNavItems("APPROVER")` คืนรายการเดียว) เข้าสู่โหมด "รออนุมัติ" ทันที ไม่มีแท็บสร้างใบเบิก
- ความต้องการ: เห็นเฉพาะของที่รอตัดสินใจ + ปุ่มอนุมัติ/ปฏิเสธพร้อมสรุปค่าจริงของใบ (สินค้า/จำนวน/เส้นทาง/ผู้เบิก)

### 1.3 ตาราง "ใครเห็นอะไร"

### 1.4 บริบทที่บังคับดีไซน์

- **Mobile-first ผ่าน `sm:` เท่านั้น** — คลาสเปล่า = มือถือ, `sm:` = จอใหญ่ (ฟอร์มสร้างใบเบิกและหน้าประวัติใช้ `lg:` พับคอลัมน์ได้แต่โครงฐานยังเป็นมือถือ) Breakpoint ที่รองรับ: ฐาน <640px, `sm:` ≥640px, `lg:` ≥1024px (เฉพาะหน้าสำนักงาน)
- หน้าปฏิบัติงานในคลัง (คิวงาน + modal พนักงาน): กติกา `stockify-readable` เต็มข้อ — สเกลตัวอักษรขั้นต่ำ, touch target, คอนทราสต์เหนือ AA
- หน้าสำนักงาน (ฟอร์มสร้างใบ, รออนุมัติ, ประวัติ): ระบบ Modern Ops เต็มรูปแบบ

## 2. User Flow

### 2.1 Flow พนักงานคลัง — เบิกสินค้าตามใบ (`/staff/transfer`)

1. พนักงานเปิดแอปและสแกน QR เข้าโกดังของตน → เมนู "เบิกสินค้า" (ไอคอน staff) เปิดหน้า `/staff/transfer`
2. หน้าแสดงการ์ดหัว: ชื่อพนักงาน + **โกดังปัจจุบัน** + ปุ่ม "รีเฟรช" — ใต้แถวเป็นคิวใบเบิกทั้งหมดของโกดังต้นทางที่ตรงกับโกดังปัจจุบัน (สถานะ PENDING/ACKNOWLEDGED)
3. พนักงานอ่านการ์ดใบเบิก: ชื่อสินค้า + บาร์โค้ด/SKU + **ตำแหน่งที่ต้องไปหยิบ** + จำนวน "N ชิ้น" + เส้นทาง "โกดังต้นทาง → โกดังปลายทาง" + badge สถานะขั้นตอน live
4. กดปุ่ม **"เริ่มเบิกสินค้า / สแกน"** (หรือ "สแกนต่อ" ถ้าทำค้างไว้) → เปิด modal เต็มจอ ขั้นที่ 1 จาก 2
5. **ขั้นที่ 1 — สแกนสินค้า:** ยิงบาร์โค้ดบนตัวสินค้า (หรือพิมพ์รหัส + Enter)
   - 5a. รหัสตรง → ข้อความยืนยันสั้น + ระบบข้ามไป **ขั้นที่ 2** ทันที (ตาม A1 ไม่มีขั้นสแกนชั้นต้นทาง)
   - 5b. รหัสไม่ตรง → แถบ error แดงแสดง "ที่สแกนมา" เทียบ "ที่ต้องการ" → พนักงานสแกนใหม่ (โฟกัสค้างที่ช่อง ไม่ต้องแตะ)
   - 5c. สแกนโดนเลขที่ใบงาน TRF → error เตือนว่านั่นคือเลขเอกสาร ไม่ใช่บาร์โค้ดสินค้า
6. **ขั้นที่ 2 — สแกนตำแหน่งปลายทาง:** ยกของไปถึงชั้นปลายทางในโกดังปลายทาง แล้วยิงบาร์โค้ดชั้นวาง
   - 6a. ชั้นมีจริงในโกดังปลายทาง → แผงเขียวยืนยันแสดงรหัสชั้นตัวใหญ่ + ชื่อโกดัง + ลิงก์ "สแกนใหม่"
   - 6b. ชั้นไม่มีจริง → error พร้อมตัวอย่างชั้นที่มีอยู่จริง (เช่น A1, A2)
7. กด **"ยืนยันการเบิก (ส่งให้ Admin อนุมัติ)"** → ปุ่มสถานะกำลังบันทึก (disabled + spinner + ข้อความ)
8. บันทึกสำเร็จ → จอสรุปสำเร็จ "เบิกสินค้าและส่งข้อมูลเรียบร้อยแล้ว" → กด "ปิดหน้าต่าง / กลับสู่รายการ"
9. ใบหายจากคิวของพนักงานทันที (optimistic) สถานะเปลี่ยนเป็น WAITING_APPROVAL — ปลายทางฝั่งแอดมินเห็นในแท็บ "รออนุมัติ" ผ่าน sync
10. ทางออกกลางทาง: กด X หรือ Esc ปิด modal ได้ทุกขั้น — ระบบเก็บ `current_step` ไว้ เข้าใหม่ผ่าน "สแกนต่อ" เริ่มจากขั้นเดิม

**จุดที่ flow ต่างจากแอดมิน:** พนักงานไม่มีแท็บสร้างใบ, ไม่เห็นแท็บรออนุมัติ, เห็นเฉพาะงานของโกดังตน (แอดมินเห็นคิวรวม), ไม่มีปุ่มอนุมัติ/ยกเลิกใด ๆ

### 2.2 Flow แอดมิน — สร้างใบเบิก (`/movements/transfer`, แท็บ "สร้างใบเบิกสินค้า")

1. เปิดเมนู "เบิกสินค้า" → แท็บสวิตช์ 3 ช่อง (สร้างใบเบิกสินค้า | รายการที่ต้องไปเบิก [badge แดง = จำนวนคิว] | รออนุมัติ [badge เหลือง]) เริ่มที่แท็บสร้างใบ
2. เลือก **โกดังต้นทาง** (ค่าเริ่มต้น = โกดังที่กำลังทำงานอยู่) และ **โกดังปลายทาง** (ซ่อนโกดังต้นทางออกจากตัวเลือก สลับต้นทางแล้วระบบดันปลายทางให้ไม่ซ้ำอัตโนมัติ)
3. ช่องเลือกสินค้าเชื่อมข้อมูลเฉพาะสินค้าของ**โกดังต้นทาง** ค้นด้วยชื่อ/SKU/บาร์โค้ด → คลิกเพิ่มเข้ารายการ (ทำซ้ำได้หลายรายการ เพิ่มซ้ำ = จำนวน +1)
4. การ์ดแต่ละรายการ: ปุ่ม −/+ ปรับจำนวน (cap ที่สต็อกคงเหลือของโกดังต้นทาง แสดง "คงเหลือ: N ชิ้น"), ไอคอนลบรายการ, ลิงก์ "ล้างทั้งหมด"
5. กดปุ่มสร้าง (ปุ่มโชว์สรุปสด เช่น "สร้างรายการเบิกสินค้า (3 รายการ / 1,250 ชิ้น)") → validation:
   - ผ่าน → สร้างเอกสาร **ทีละรายการ** (พร้อมกัน, มี idempotency key กันใบซ้ำ) → แถบเขียว "สร้างรายการเบิกสินค้าสำเร็จ N รายการ (บันทึกใน 'รายการที่ต้องไปเบิก' เรียบร้อยแล้ว)" → ฟอร์มล้างรายการ คงโกดังไว้
   - ไม่ผ่าน → แถบแดงใต้ช่อง (ข้อความตามหัวข้อ 6.2) หรือแถบ error รวมด้านบนของฟอร์ม
6. ใบที่สร้างโผล่ในแท็บ "รายการที่ต้องไปเบิก" สถานะ "รอดำเนินการ (ยังไม่เริ่ม)" — พนักงานในโกดังต้นทางเห็นทันที

### 2.3 Flow แอดมิน/APPROVER — ตรวจและอนุมัติ

1. เปิดแท็บ "รออนุมัติ" (APPROVER: เข้าเมนูมาอยู่หน้านี้ทันที พร้อม badge "รออนุมัติ N รายการ")
2. การ์ดใบรออนุมัติแสดง: สินค้า/จำนวน/เส้นทาง + **ตำแหน่งที่สแกนจริง (ต้นทาง → ปลายทาง)** + ผู้สร้างใบ + ผู้เบิก + เวลาเบิก
3. กด "อนุมัติการเบิก" → ยืนยันด้วยค่าจริง (หัวข้อ 6.4) → สถานะ optimistic เป็น COMPLETED, ระบบตัดสต็อกต้นทาง/เพิ่มปลายทางฝั่งเซิร์ฟเวอร์ และแท็กรายการเข้า Express (ISSUE + TRANSFER)
   - เซิร์ฟเวอร์ล้มเหลว → rollback ใบกลับเข้าคิวรออนุมัติ + แจ้ง "อนุมัติไม่สำเร็จ: <เหตุผล>"
4. หรือกด "ปฏิเสธ" → ยืนยัน → สถานะ REJECTED ใบออกจากคิว (history แสดงเป็น "ยกเลิก")
5. ยกเลิกใบที่ยังไม่เสร็จ (PENDING/ACKNOWLEDGED/WAITING_APPROVAL) ได้จากปุ่ม "ยกเลิก" → ยืนยัน → CANCELLED

### 2.4 Flow แอดมิน — ประวัติ (`/movements/transfer/history`)

1. เปิดเมนู "ประวัติเบิกสินค้า" → การ์ดสรุป 4 ใบ (รายการทั้งหมด / จำนวนชิ้นรวม / เบิกสำเร็จ / รออนุมัติ+กำลังเบิก)
2. กรอง: ช่องค้นหา (เลขเอกสาร, บาร์โค้ด, รหัส/ชื่อสินค้า, ชื่อผู้เบิก) + สถานะ + โกดังต้นทาง + โกดังปลายทาง + ช่วงวันที่ (ค่าเริ่มต้น "วันนี้") + เลือกจำนวนแถว
3. กดแถว → modal "รายละเอียดใบเบิกสินค้า" (เลขเอกสารคัดลอกได้, ตำแหน่งต้นทาง-ปลายทาง, ผู้สร้าง/ผู้เบิก, เวลา)
4. ปุ่มส่งออก CSV (ชื่อไฟล์ `transfer_history_YYYY-MM-DD.csv`, BOM สำหรับ Excel ไทย)

### 6.2 ฟอร์มสร้างใบเบิก — validation และข้อความจริง

| เงื่อนไข | ตำแหน่งแสดง | ข้อความ (ตามโค้ด — ใช้ตรงตามนี้ใน QA) |
|---|---|---|
| ไม่เลือกโกดังต้นทาง/ปลายทาง | ใต้ช่อง, 14px หนา rose-700 | "กรุณาเลือกโกดังต้นทาง" / "กรุณาเลือกโกดังปลายทาง" |
| ต้นทาง = ปลายทาง (กันไว้ที่ logic ด้วย: ตัวเลือกปลายทางกรองต้นทางออก + สลับต้นทางแล้วดันค่า) | แถบ error รวม | "โกดังต้นทางและโกดังปลายทางต้องไม่ซ้ำกัน" |
| ไม่มีสินค้าในรายการ | แถบ error รวม | "กรุณาค้นหาและเลือกสินค้าที่ต้องการโอนอย่างน้อย 1 รายการ" |
| จำนวน > สต็อกต้นทาง | แถบ error รวม | `จำนวนที่จะโอนสำหรับ "<ชื่อสินค้า>" (N ชิ้น) เกินกว่าจำนวนที่มีในโกดังต้นทาง (คงเหลือ M ชิ้น)` |
| สร้างล้มเหลวทุกรายการ | แถบ error รวม | `ไม่สามารถสร้างใบเบิกสินค้าได้: "<ชื่อสินค้า>": <เหตุผลจากเซิร์ฟเวอร์>` |
| สร้างได้บางรายการ | แถบเตือน | `สร้างสำเร็จ N รายการ แต่พบข้อผิดพลาดในบางรายการ: <รายการที่พลาด>` |
| ชนกันระหว่างส่งซ้ำ (idempotency) | ต่อรายการในแถบ error | `"<ชื่อสินค้า>": รายการถูกบันทึกไปแล้วหรือกำลังประมวลผล กรุณารอสักครู่` |

กติกาฟอร์ม: ป้ายกำกับ**เหนือ**ช่องเสมอ · ตัวบอกบังคับกรอก `*` สี rose-600 · ช่องเลขจำนวนกรองตัวอักษรนอก 0-9 ทิ้ง · เผลอล้างช่องเลขแล้วเลื่อนโฟกัสออก → คืนค่าเป็น 1

### 6.3 การสแกนบาร์โค้ด (ช่องสแกนทั้ง 2 ขั้น)

- อุปกรณ์: เครื่องยิง (คีย์บอร์ดเสมือน + Enter) และพิมพ์มือ — ทั้งสองเข้าช่องเดียวกัน, โฟกัสอัตโนมัติเมื่อเปิดขั้น และ**คืนโฟกัสหลังตรวจรหัสจบทุกครั้ง**
- ระหว่างประมวลผล: `readOnly` + `aria-busy` — ห้าม `disabled` (กติกา stockify-warehouse-state) และกันสแกนซ้อนด้วยล็กกันซ้ำ 500ms (`isStepTransitioning`)
- **กฎจับคู่รหัสสินค้า (ขั้น 1)** — ผ่านถ้าตรงอย่างใดอย่างหนึ่ง (หลัง normalize: ตัดช่องว่าง `- _ #`, ตัดคำนำหน้า `loc-`, lowercase):
  1. ตรงบาร์โค้ดสินค้าเต็ม, 2. ตรง SKU, 3. ตรงรหัสสินค้า (มี/ไม่มีคำนำ `prod-`), 4. เลข 4 ตัวท้ายตรงท้ายของบาร์โค้ด/SKU
- **กฎจับคู่ชั้นวาง (ขั้น 2)** — ตรง `location_id` / `location_code` / `location_name` / `shelf_code` ของตำแหน่งที่ active ใน**โกดังปลายทางเท่านั้น**; ถ้ายังไม่โหลดรายชื่อชั้นจะดึง API ก่อน ไม่มีจริง → error + แนบตัวอย่างชั้นสูงสุด 4 ชั้น
- ผลทุกครั้งต้องฟ้องทันทีและใหญ่: ผ่าน = ข้อความ/แผงเขียว, ไม่ผ่าน = แถบแดงที่ไม่หายเองจนกว่าจะสแกนครั้งใหม่ (ค่าใหม่ทับข้อความเดิม)

### 6.4 การยืนยันก่อนบันทึก (confirm แบบอ่านง่าย)

แทน `window.confirm` เดิมด้วย modal W9 — เหตุผล: ยืนยันด้วยค่าจริงตามกติกา readable ("ทวนค่าก่อนบันทึก") และปุ่มภาษาไทยของเบราว์เซอร์ (OK/Cancel) อ่านยากสำหรับผู้ใช้เป้าหมาย

| การกระทำ | ข้อความหัวเรื่อง | ค่าที่ต้องทวน | ผลที่ต้องบอกล่วงหน้า |
|---|---|---|---|
| อนุมัติ | "อนุมัติใบเบิกสินค้า?" | เลขเอกสาร, ชื่อสินค้า, จำนวน, เส้นทาง | "ระบบจะตัดสต็อกต้นทางและเพิ่มปลายทาง" |
| ปฏิเสธ | "ปฏิเสธใบเบิกสินค้า?" | เลขเอกสาร, สินค้า, จำนวน | "ใบงานจะปิดเป็นสถานะปฏิเสธ และไม่มีการตัดสต็อก" |
| ยกเลิก | "ยกเลิกใบเบิกสินค้า?" | เลขเอกสาร, สินค้า, จำนวน | "ใบงานจะถูกยกเลิก พนักงานจะไม่เห็นใบนี้อีก" |
| กดยืนยันใน modal พนักงาน (step 2) | ไม่ต้อง modal ซ้อน — แผงเขียว W5 คือการยืนยัน (โชว์ชั้น+โกดังก่อนกด) | — | — |
| เคลียร์คิวที่เสร็จแล้ว (cleanup) | "เคลียร์รายการที่ทำเสร็จแล้ว?" | จำนวนรายการที่จะถูกลบ | "รายการเหล่านี้ยังอยู่ในหน้าประวัติ" |

ข้อความ error จากยืนยัน/ส่ง (โค้ดปัจจุบัน): "อนุมัติไม่สำเร็จ: <เหตุผล>", "ยกเลิกไม่สำเร็จ: <เหตุผล>", "ปฏิเสธไม่สำเร็จ: <เหตุผล>", "เกิดข้อผิดพลาดในการเชื่อมต่อเซิร์ฟเวอร์" — ต้องแสดงในแถบ/ทรงของบ้าน ไม่ใช่ `alert()`

### 6.5 Responsive

- ฐานมือถือ <640px ทุกหน้า; `sm:` ≥640px: ฟอร์มพับ 2 คอลัมน์ (`grid-cols-1 sm:grid-cols-2`), แท็บสวิตช์ข้อความเรียงแนวนอน, ประวัติจัดการกริด
- `lg:` ≥1024px เฉพาะหน้าประวัติ (กริดตัวกรอง 12 คอลัมน์)
- ตารางประวัติบนมือถือ: ทำเป็นการ์ดต่อรายการ (เกิน 3 คอลัมน์ห้ามเป็นตาราง — กติกา readable) ดูข้อเสนอหัวข้อ 10.4
- Modal พนักงาน: เต็มจอ `h-[100dvh]` เลื่อนได้, `max-w-lg` กึ่งกลางบนจอใหญ่, ล็กสกอลล์พื้นหลัง, ปุ่มหลักลอยเหนือ safe-area

### 6.6 Motion (กติกา stockify-motion)

| จุด | คลาส |
|---|---|
| Modal/overlay เปิด | `.fade-in` (overlay) + `.scale-in` (panel) — **ห้าม** `animate-in fade-in zoom-in-95` (คลายตาย ไม่ทำงาน) |
| แถบ error/success, แผงเขียวยืนยัน | `.fade-in` |
| hover/สลับแท็บ/badge | `transition-colors duration-150/200` |
| เส้นความคืบหน้า step indicator | `transition-all duration-300` |
| spinner (ส่งข้อมูลจริงเท่านั้น) | `animate-spin motion-reduce:animate-none` + ข้อความกำกับเสมอ |
| ตัวเลขทุกตัว | นิ่ง — ห้าม count-up/เลขวิ่ง (ยกเว้นการ์ดสรุปประวัติ: count-up ≤750ms + `prefers-reduced-motion`) |
| exit | ปิด modal ≤150ms — พนักงานกดงานต่อเนื่อง |

### 6.7 Accessibility (ขั้นต่ำ WCAG AA — บังคับเหนือ AA ตามบ้าน)

- คอนทราสต์ข้อความ: หลัก `text-slate-900` (17.85:1) · รองต่ำสุด `text-slate-600` (7.58:1) — **ห้าม** slate-400/500 กับข้อความมีความหมาย · เขียวข้อความใช้ `emerald-700` (5.48:1) ไม่ใช่ 600 (3.77:1) · แดงข้อความใช้ `rose-700` · เหลืองข้อความใช้ `amber-700/800`
- ห้ามสื่อสถานะด้วยสีเดียว — badge ทุกอัน = จุดสี + ข้อความ
- ทุกช่องกรอกมี `<label>` จริง (ไม่ใช้ placeholder แทนป้าย), modal ปิดด้วย Esc, ปุ่มไอคอนมี `aria-label` หรือข้อความประกบ
- ช่องสแกน `aria-busy` ระหว่างตรวจ, ข้อความ error ผูกกับช่องด้วย `aria-describedby` เมื่อแก้
- ภาษาไทยแบบสั่งงาน: "กรุณา…" สั้น ตรง บอกทางออกด้วย `—` · ไม่ใช้ "ท่าน" · ไม่ฝังอิโมจิแทนไอคอน (ข้อความระบบเดิมที่มีอิโมจินำหน้า ให้ตัดออกและใช้ไอคอน SVG)

## 7. สถานะใบเบิก — State Machine + Badge

ค่าจริงจาก `transfer-notification-utils.ts`: `status: PENDING | ACKNOWLEDGED | WAITING_APPROVAL | COMPLETED | CANCELLED | REJECTED` และ `current_step: 0-4` (0 = ยังไม่เริ่ม, 1 = กำลังสแกนสินค้า, 2 = กำลังหยิบต้นทาง [ปัจจุบันถูกข้าม — A1], 3 = กำลังสแกนปลายทาง, 4 = ส่งรออนุมัติ)

```
                       ┌──────────────┐  admin/APPROVER ยกเลิก
  admin สร้างใบ ──────▶ │   PENDING    │ ─────────────────────┐
  (current_step 0)      │ รอดำเนินการ   │                      ▼
                       └──────┬───────┘                ┌──────────┐
            พนักงานเปิดงาน      │                        │ CANCELLED│
            (step 1-3)        ▼                        │  ยกเลิก   │
                       ┌──────────────┐                └──────────┘
                       │ ACKNOWLEDGED │  admin/APPROVER ยกเลิก (เส้นเดียวกับข้างบน)
                       │  กำลังทำ      │ ────────────────────▶ CANCELLED
                       └──────┬───────┘
              พนักงานกด "ยืนยันการเบิก"  (step 4)
                              ▼
                       ┌───────────────────┐
                       │ WAITING_APPROVAL  │
                       │ รอ Admin อนุมัติ    │
                       └──┬─────────────┬──┘
              admin/APPROVER│             │admin/APPROVER
                อนุมัติ      ▼             ▼ ปฏิเสธ
                 ┌──────────────┐      ┌──────────┐
                 │  COMPLETED   │      │ REJECTED │
                 │ ตัดสต็อกแล้ว    │      │ (แสดงรวม │
                 │ + แท็ก Express │      │  เป็น     │
                 └──────────────┘      │ "ยกเลิก") │
                                       └──────────┘
  ทางกลับฉุกเฉิน: approve/cancel/reject ล้มเหลวฝั่งเซิร์ฟเวอร์ → rollback กลับสถานะเดิม
  (ไม่มีการแก้ใบ/แก้จำนวนหลังสร้าง — แก้ = ยกเลิกแล้วสร้างใหม่)
```

| สถานะ | ข้อความ badge (ห้ามแต่งเพิ่ม) | สี badge (ตาม Modern Ops) |
|---|---|---|
| PENDING / ACKNOWLEDGED + step 0 | รอดำเนินการ (ยังไม่เริ่ม) | `bg-slate-100 text-slate-700` + จุด `bg-slate-500` |
| กำลังทำ step 1 | กำลังสแกนสินค้า | `bg-emerald-100 text-emerald-700` + จุด emerald (ปัจจุบันโค้ดใช้ sky — ให้รวมเป็นเฉด emerald ตามข้อ 10.6) |
| กำลังทำ step 2 (ถ้าเปิดใช้ A1) | กำลังหยิบสินค้าต้นทาง | `bg-amber-100 text-amber-700` + จุด amber |
| กำลังทำ step 3 | กำลังสแกนตำแหน่งปลายทาง | `bg-emerald-100 text-emerald-700` + จุด emerald |
| WAITING_APPROVAL (step 4) | เบิกแล้ว (รอ Admin อนุมัติ) | `bg-amber-100 text-amber-800` + จุด `bg-amber-500` |
| COMPLETED | เบิกสำเร็จ | `bg-emerald-100 text-emerald-700` + จุด emerald |
| CANCELLED / REJECTED | ยกเลิก | `bg-rose-100 text-rose-700` + จุด rose (rose ใช้ได้เฉพาะสถานะทำลาย/ยกเลิก) |

step ที่กำลังทำ (1-3) แสดง `(N/3)` mono ต่อท้าย badge ได้ — badge ตัวอักษร ≥14px หนา ห้ามลดเหลือ 11px (ต่างจากโค้ดปัจจุบัน)

## 8. Design Tokens — คลาส Tailwind ที่ใช้จริง (Modern Ops)

> ใช้กับทุกองค์ประกอบที่แตะ/สร้างใหม่ในเมนูนี้ ค่าที่โค้ดปัจจุบันเบี่ยงออก รวบไว้ที่หัวข้อ 10 อย่ารื้อทั้งไฟล์พร้อมกัน — แก้ตามจุดที่แตะ

**พื้น/การ์ด**

```tsx
/* พื้นหน้า */                 bg-[#F4F6F3]
/* การ์ดหลัก */                bg-white rounded-[20px] border border-black/[.07] p-4 sm:p-6
  shadow-[0_1px_2px_rgba(16,22,20,.04),0_14px_36px_-20px_rgba(16,22,20,.14)]
/* การ์ดลูกในการ์ดแม่ */        bg-black/[.015] border border-black/[.06] rounded-2xl (ไม่มีเงา)
/* ผิวลอย (modal W9, toast) */ bg-white rounded-2xl shadow-xl border border-black/[.06]
```

**ปุ่ม**

```tsx
/* หลัก */      w-full py-3 sm:py-3.5 rounded-xl bg-emerald-600 hover:bg-emerald-700 text-white
  font-bold text-[15px] shadow-lg shadow-emerald-600/20 active:scale-95 disabled:opacity-50 cursor-pointer
/* หมึก (จอสรุปสำเร็จ) */ px-3.5 py-2 rounded-xl bg-[#0F1712] text-white text-sm font-bold hover:bg-black
/* รอง */       px-4 py-2.5 rounded-xl bg-white border border-black/10 text-slate-700
  font-semibold text-sm hover:bg-black/[.04]
/* ทำลาย */     px-4 py-2 rounded-xl bg-rose-600 hover:bg-rose-700 text-white font-bold text-sm
  (แบบขอบ: bg-white border border-rose-200 text-rose-700 hover:bg-rose-50)
```

**ช่องกรอก / สแกน**

```tsx
/* ช่องปกติ */  w-full px-3.5 py-2.5 rounded-xl bg-slate-50 border border-slate-200 text-slate-900
  placeholder-slate-500 focus:outline-none focus:border-emerald-500 focus:ring-2 focus:ring-emerald-500/20 text-[15px]
/* ช่องจำนวน/บาร์โค้ด */ + font-mono font-bold text-lg tabular-nums
/* select โกดัง */ py-3.5 sm:py-4 rounded-2xl border-2 border-slate-300 text-base sm:text-lg font-bold
```

**Badge สถานะ**

```tsx
<span className="inline-flex items-center gap-1 px-2 py-0.5 rounded-full text-[13px] font-bold
  bg-emerald-100 text-emerald-700"><span className="w-1.5 h-1.5 rounded-full bg-emerald-500"/>เบิกสำเร็จ</span>
/* amber-100/amber-700 = รออนุมัติ · rose-100/rose-700 = ยกเลิก · slate-100/slate-600 = รอดำเนินการ */
```

**ตาราง (เฉพาะ `sm:` ขึ้นไป)**

```tsx
<div className="bg-white rounded-[20px] border border-black/[.07] overflow-hidden">
  <div className="overflow-x-auto">
    <table className="w-full text-[15px]">
      <thead><tr><th className="px-5 py-3 text-left text-[13px] font-semibold text-[#5B6660] uppercase tracking-wider">…</th></tr></thead>
      <tbody className="divide-y divide-black/[.05]"> … (ไม่ใส่ hover:bg ที่ <tr> — globals.css ทับด้วย indigo !important)
```

**สี semantic**

| ความหมาย | คลาส | หมายเหตุ |
|---|---|---|
| ปฏิบัติการ/ปกติ/สำเร็จ | emerald-600 (พื้นปุ่ม) / emerald-700 (ข้อความ) / emerald-100 (badge) | สี accent เดียวของระบบ — ของเดิมที่ใช้ indigo/purple/sky ให้แทนเมื่อแตะ |
| รอ/เตือน/ต่ำกว่าเกณฑ์ | amber-500 (จุด) / amber-100+amber-700 (badge) | ป้ายและไอคอนเท่านั้น |
| ทำลาย/ยกเลิก/ปฏิเสธ | rose-600 (ปุ่ม) / rose-700 (ข้อความ) | **rose ห้ามใช้นอกเรื่องทำลาย** |
| หมึก | `text-[#0F1712]` (หลัก) / `text-[#5B6660]` (รอง) | ห้าม slate-400/300 กับข้อความ |
| โค้ด/รหัส | `.mono` (IBM Plex Mono) · เลข display `.disp` (Space Grotesk) + `tabular-nums` | บาร์โค้ดเป็น string เสมอ ผ่าน `to8DigitBarcode()` เมื่อพิมพ์สัญลักษณ์บาร์โค้ด |

**Motion / ฟอนต์ / พื้นที่สัมผัสสรุป**

- อนิเมชัน: `.fade-in`, `.scale-in`, `duration-150/200/300`, `motion-reduce:animate-none` กับของวน — ห้าม `animate-in…`, ห้าม animation library
- ฟอนต์: Sarabun (ไทย, 500-600), Space Grotesk `.disp` (เลขสถิติ), IBM Plex Mono `.mono` (TRF-..., SKU, ชั้นวาง)
- Touch target: หลัก ≥56px · stepper ± ≥48px · รอง/ไอคอน ≥44px · gap ≥12px

## 10. ช่องว่างและข้อเสนอแนะ — วิจารณ์โค้ดปัจจุบัน

จัดลำดับตามผลต่อผู้ใช้จริง รูปแบบ: หน้าจอ → สิ่งที่เห็นในโค้ด → ตามสเปกต้องเป็น

1. **ขนาดตัวอักษรเล็กเกินทุกไฟล์ (รุนแรงสุดของแอป)** — วัดโดยสกิล readable: โฟลเดอร์ transfer มีข้อความ ≤12px รวม **147 จุด** (text-xs 100, text-[11px] 38, text-[10px] 9) และหน้าประวัติเป็นแหล่งใหญ่ (ตาราง `text-xs`, สรุปการ์ด `text-[11px]`, "ล้างตัวกรอง" `text-[10px]`) → ตามสเปกหัวข้อ 6.7/8 ต้องขยับเป็นสเกลขั้นต่ำ 14/16/20px ให้ครบจุดที่ผู้ใช้อ่านจริง เริ่มจาก `TransferStaffWorkflowModal.tsx` (จอที่พนักงานตัดสินใจ), ตามด้วย `TransferNotificationList.tsx`, แล้ว `history/page.tsx` (อย่าแตะ `_hooks/use-transfer-movement.ts` ระหว่างงานปรับหน้าตา — เป็นตรรกะล้วน 1,362 บรรทัด)

2. **ขั้นที่ 2 (หยิบสินค้าต้นทาง) ถูก comment ทิ้งครึ่ง ๆ** — `TransferStaffWorkflowModal.tsx` มีบล็อก `staffStep === 2` ทั้งบล็อกถูกคอมเมนต์ แต่ hook ยังมี `handleVerifySourceLocationBarcode`/`sourceAllocations`/ปุ่มกล้อง SOURCE_LOCATION ทำงานอยู่ และการ์ด badge ยังมีสถานะ "กำลังหยิบสินค้าต้นทาง (2/3)" ที่จะไม่มีวันเกิด → ทางเลือก: (ก) ยืนยันข้ามถาวร แล้ว**ลบโค้ด step 2 ทั้งชุด** ให้เหลือ 2 ขั้นตามสเปกนี้ (แนะนำ — ผลลัพธ์: ไม่รู้ว่าหยิบจากชั้นไหน ตรวจนับย้อนหลังยาก) หรือ (ข) เปิดกลับเป็น 3 ขั้นตามสูตรฉบับอ่านง่ายใน `stockify-readable/references/issue-flow.md` (แถบ "ยังขาดอีก N ชิ้น" ตัว 30px) — ต้องตัดสินก่อนเขียนโค้ด (A1)

3. **การยืนยันสำคัญใช้ `window.confirm`/`alert` ของเบราว์เซอร์** — อนุมัติ/ปฏิเสธ/ยกเลิก/เคลียร์คิว ทั้งหมดผ่าน confirm เปลือกเบราว์เซอร์ (ปุ่ม OK/Cancel ภาษาอังกฤษ, ไม่ทวนค่าจริง, ผู้ใช้สายตายาวอ่านยาก) → ตามสเปก 6.4/W9 ต้องเป็น modal ของบ้านที่ทวนเลขเอกสาร+สินค้า+จำนวน+ผลที่จะเกิด

4. **หน้าประวัติเป็นตาราง 6 คอลัมน์บนมือถือ** — `history/page.tsx` ใช้ `<table>` + `overflow-x-auto` ตลอด → กติกา readable: เกิน 3 คอลัมน์บนมือถือต้องเป็นการ์ดต่อรายการ (ชื่อ+จำนวน+สถานะ+เวลา กดเปิดรายละเอียดเหมือนเดิม) ให้ทำที่ `sm:` ต่ำกว่าเป็นการ์ด, ตารางคงไว้ตั้งแต่ `sm:` ขึ้นไป

5. **ข้อความ error/success ฝังอิโมจินำหน้าและสำนวนเหลื่อม** — ทั้ง hook ใช้เครื่องหมายถูก/กากบาทอิโมจินำหน้าข้อความ (readable ข้อ 5 ห้ามใช้อิโมจิแทนไอคอน), และข้อความปฏิเสธพิมพ์ว่า "ยืนยันปฏิเสธ**ใบย้ายสินค้า** TRF-..." ทั้งที่เป็นใบเบิก → ตัดอิโมจิ ใช้ไอคอน SVG ในแถบ, แก้สำนวนเป็น "ใบเบิกสินค้า"

6. **สีเก่า (indigo/purple/sky) และเศษธีมค้างทั่วเมนูนี้** — focus ring ช่อง select เป็น indigo, แบดจ์จำนวน/step 3 เป็น indigo, หัวหน้าพนักงานจุดสี purple, spinner ประวัติเป็น purple, badge step 1 เป็น sky → Modern Ops ให้ emerald เป็น accent เดียว: แทนเมื่อแตะไฟล์ (ตามกติกา "เก็บกวาดเมื่อเจอ" ของ stockify-ui) ไม่ต้องตั้งงานรื้อทั้งชุดพร้อมกัน

7. **คลาสอนิเมชันตาย `animate-in fade-in zoom-in-95`** — ใน `TransferStaffWorkflowModal.tsx` (แผงเขียวยืนยัน + จอสรุปสำเร็จ) และ `animate-bounce` บน toast คัดลอกของหน้าประวัติ → แทนด้วย `.fade-in`/`.scale-in` และให้ toast ขยับครั้งเดียวตอนโผล่ (กติกา stockify-motion ข้อ 8/ข้อ 6)

8. **ปุ่มลบรายการในฟอร์มเป็นไอคอนเปล่า** — `TransferForm.tsx` ปุ่มถังขยะ 44px ไม่มีข้อความ อาศัย `title` เท่านั้น → ใส่คำ "ลบ" คู่ไอคอน หรือย้ายเป็นปุ่มขอบ rose แบบ "เอาออกจากรายการ" ตามสูตร issue-flow (เป้าชัด ผู้สูงอายุไม่ต้องเดา)

9. **ปุ่มกล้องสแกนตายใน modal พนักงาน** — `onOpenStaffCamera` รับมาแต่ไม่มีปุ่มเรียก, `CameraBarcodeScannerModal` ติดตั้งในหน้าแต่เปิดไม่ได้เลยในเมนูนี้ → ทางเลือก: เพิ่มปุ่มรอง "สแกนด้วยกล้อง" ใต้ช่องสแกนทั้ง 2 ขั้น (เป้า ≥44px) หรือถอด prop ออกก่อนจะกลับมาทำ — อย่าทิ้งค้างแบบนี้ (A7)

10. **แถบ error รวมไม่รองรับหลายบรรทัด** — ข้อความสร้างบางส่วนล้มเหลวประกอบด้วย `\n` แต่ div ปกติไม่ตัดบรรทัดตาม → เติม `whitespace-pre-line` ที่แถบ error ของ `TransferForm`

11. **`TransferNotificationList` auto-fetch ตำแหน่งต่อ SKU แบบไม่มี debounce/สถานะโหลด** — effect ยิง `/api/products?search=` ซ้ำตามการเปลี่ยนของ `skuLocationMap` (เขียน state ใน loop ทำให้ effect รันใหม่) → ควรรวบเป็น request ครั้งเดียวต่อการ์ดชุด + เก็บผลใน ref ก่อน set ครั้งเดียว (ประหยัดคำขอ + กันกระพริบ) ฝั่ง QA: สังเกต Network tab ขณะเปิดคิว 10 ใบ

12. **Role `MANAGER`/`STAFF` เป็นคนตัดบ้าน** — ประกาศใน `UserRole` แต่ไม่อยู่ใน `roles` ของเมนูใด ๆ (`nav-items.tsx`) ผู้ใช้ role นี้จะล็อกอินแล้วเห็น Sidebar เปล่า → ยืนยันกับเจ้าของระบบ: จะเพิ่มใน roles ของเมนูที่เหมาะสม หรือลบออกจาก type ให้ตรงความจริง (A6)

13. **หน้า `/movements/transfer` ไม่มีการ์ดกันเข้าของ role ที่พิมพ์ URL ตรง** — staff ที่พิมพ์ URL จะเห็นแท็บสวิตช์ของแอดมิน (โหมดสร้างใบ) → ควร redirect ตาม role ไป `/staff/transfer` ที่ระดับหน้า ไม่พึ่งเมนูเท่านั้น

14. **ของที่ดีและต้องรักษาไว้ (ห้ามถอดระหว่างแก้)** — idempotency key ต่อรายการกันใบซ้ำตอน retry · optimistic UI พร้อม rollback ที่ถูกต้องทั้ง approve/cancel/reject · เก็บ `current_step` ให้พนักงานกลับมา "สแกนต่อ" ได้ · กรองชั้นวางที่สต็อกหมดออกจากคำแนะนำตำแหน่ง · error message บอก "ที่สแกน vs ที่ต้องการ" · BOM ใน CSV ไทย
