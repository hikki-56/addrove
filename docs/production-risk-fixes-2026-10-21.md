# แก้จุดเสี่ยงระบบผลิต — 21 ตุลาคม 2026

แก้ครบ 3 ประเด็นจาก [ผลตรวจเพิ่มเติม](production-risk-review-2026-10-21.md) ในโค้ดแอป ไม่มีการเปลี่ยนข้อมูลสต็อกหรือรายงานผลิตจริงระหว่างพัฒนา

## การเปลี่ยนแปลง

1. **กันใช้วัตถุดิบที่จองให้งานผลิต**: `PostgresStockSummaryRepository.applyChanges` ตรวจหลังปรับทั้งชุดว่ายอดในตำแหน่งที่เปิดใช้งานยังครอบคลุมยอดจองของสินค้าในโกดังนั้น หากไม่พอจะ rollback ทั้ง transaction จึงครอบคลุมเส้นทางเบิก ย้ายข้ามคลัง กลับรายการ และปรับสต็อกที่ใช้ repository กลาง ไม่ต้องให้แต่ละเมนูเรียกตัวตรวจแยกกัน ย้ายระหว่างตำแหน่งที่เปิดใช้งานในโกดังเดียวกันได้ เพราะตรวจยอดหลังครบทั้งต้นทางและปลายทาง
2. **งานผลิตใช้การจองของตัวเองได้**: เมื่อยืนยันรายงาน ตรวจวัตถุดิบจริงและการจองของงานอื่นก่อน แล้วปลดการจองของใบงานนี้ภายใน transaction เดิมเพื่อเปลี่ยนเป็นยอดใช้จริง หากรายงานบางส่วนจะจองยอดที่เหลือใหม่ หากเขียนล้มเหลว การจองเดิมกลับคืนพร้อมสต็อก ไม่มีช่วงปลดจองที่ commit แยกให้เมนูอื่นเข้ามาใช้ของได้
3. **ป้องกันกลับรายการผลิตผิดทาง**: `reverseStock` ปฏิเสธเอกสารที่ระบุ `kind: PRODUCTION_*` ทั้งก่อนและหลังถือล็อก ครอบคลุมเอกสารผลผลิตปัจจุบันและเอกสารรับเข้า/ปรับปรุงของระบบเดิม ข้อความแจ้งว่าต้องปรับรายงานผลิตและวัตถุดิบพร้อมกัน ไม่ได้เพิ่มขั้นตอนย้อนการผลิตในรอบนี้ เอกสารสต็อกทั่วไปที่ไม่ละเมิดยอดจองยังกลับรายการได้ตามเดิม
4. **แก้หมายเหตุระหว่างของขาดได้**: แก้ใบงานแล้วจองใหม่เฉพาะเมื่อเปลี่ยนสินค้า สูตร หรือเป้าหมาย การแก้ข้อความและข้อมูลที่ไม่เปลี่ยนความต้องการวัตถุดิบไม่บังคับให้ของครบ การเพิ่ม/ลดเป้าหมายยังตรวจและปรับการจองตามจริง

ใช้ schema และ writer transaction เดิม ไม่ต้องเพิ่ม migration

- หลังแก้: ชุดระบบผลิตและกลับรายการ **29 กรณีผ่าน** ใน 24.083 วินาที
