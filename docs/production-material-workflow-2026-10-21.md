# ระบบผลิตเชื่อม BOM — 21 ตุลาคม 2026

## สถานะ

เพิ่มโค้ดหน้าวางแผน รายงานผล และตัดวัตถุดิบใน workspace แล้ว ยังไม่ได้ deploy เว็บเวอร์ชันนี้ ส่วน migration `production_material_workflow` ใช้กับฐานข้อมูลที่แอปตั้งค่าใช้อยู่แล้ว โครงสร้างเพิ่มอย่างเดียว ไม่มีการสร้างรายงานผลิตหรือเปลี่ยนสต็อกจริงระหว่างทดสอบ

## ขั้นตอนใช้งาน

1. Admin สร้างงานรายวัน เลือกโต๊ะ 1–5 สินค้า สูตร BOM และเป้าหมายสินค้าดี หนึ่งงานเป็นสินค้าหนึ่งชนิดของโต๊ะหนึ่งโต๊ะ แต่ละโต๊ะจบงานได้เอง

   ช่องค้นหาสินค้าในฟอร์มเพิ่ม/แก้ไขแสดงเฉพาะสินค้าปลายทางของ BOM ที่เปิดใช้งานและมีวัตถุดิบครบตามการเชื่อมทะเบียน ไม่แสดงวัตถุดิบทั่วไป สินค้าที่ไม่มีสูตร หรือสูตรปิดใช้งาน สินค้าที่มีหลายสูตรแสดงเพียงรายการเดียว และสินค้าที่ยังไม่มีสต็อกยังค้นหาได้
2. เลือกสินค้าแล้วระบบจับคู่ BOM จากทะเบียนสินค้านั้นและแสดงวัตถุดิบอัตโนมัติ สินค้าสูตรเดียวไม่มีช่องให้เลือก BOM ซ้ำ หากมีหลายสูตร เช่น AS12 ระบบแสดงสูตรแรกตามลำดับรหัส BOM ให้ก่อน พร้อมชื่อและรายการวัตถุดิบ สามารถเปลี่ยนเป็นอีกสูตรเมื่อใช้วัตถุดิบคนละแบบ ไม่รวมวัตถุดิบข้ามสูตร ใบงานเดิมที่มีสูตรแล้วคงสูตรที่บันทึกไว้
3. Admin ระบุหลัก/รองในรายการที่ข้อมูลต้นทางว่าง และระบุอัตราแปลงเมื่อหน่วยสูตรต่างจากหน่วยสต็อก โดยกรอกว่า 1 หน่วยสูตรเท่ากับกี่หน่วยสต็อก อัตรานี้และประเภทที่เลือกเก็บกับใบงาน ไม่แก้สูตรต้นทางหรืออนุมานอัตราเอง
4. หน้าจอแสดงจำนวนผลิตได้จากวัตถุดิบหลัก ตัวหลักหลายรายการใช้รายการที่รองรับได้น้อยที่สุด และรวมความต้องการหากรหัสวัตถุดิบหลักซ้ำ ส่วนตัวรองแสดงยอดพร้อมใช้และยอดขาดแยกกัน ตัวรองเป็นของใช้ร่วมและยังต้องใช้ตามสูตร
5. ส่งงานแล้วระบบตรวจและจองทั้งหลักและรองจากโกดัง 2 เท่านั้น หักยอดจองของงานผลิตอื่นและงานขาออกก่อน หากไม่พอจะยังส่งไม่ได้ การบันทึกฉบับร่างทำได้ขณะของยังไม่ครบ
6. แก้วเห็นงานที่ส่งแล้ว กดเริ่มงานและรายงานจำนวนดี จำนวนสินค้าประกอบแล้วเสีย สาเหตุของเสีย วัตถุดิบใช้จริง และวัตถุดิบเสียเพิ่มก่อนประกอบ หากใช้ต่างจากสูตรต้องมีเหตุผล สินค้าดีต้องเลือกตำแหน่งเก็บที่เปิดใช้งานในโกดัง 2
7. ยืนยันแล้วตัดวัตถุดิบจากตำแหน่งในโกดัง 2 และเพิ่มเฉพาะสินค้าดีในธุรกรรมเดียว รายงาน ประวัติ เอกสาร และสต็อกจะยกเลิกกลับทั้งหมดเมื่อส่วนใดเขียนไม่สำเร็จ กดยืนยันซ้ำด้วยรหัสเดิมไม่ลงสต็อกซ้ำ
8. รายงานบางส่วนได้หลายรอบ โดยปรับยอดจองส่วนที่เหลือตามสินค้าดีที่ยังขาด หากจบก่อนครบเป้าให้เหตุผลและเลือกสร้างใบงานค้างฉบับร่างสำหรับ Admin ส่งผลิตต่อ ใบงานค้างใช้สำเนาสูตรเดิม

## การนับของเสีย

- “ใช้ผลิต” รวมวัตถุดิบที่ใช้กับสินค้าดีและสินค้าที่ประกอบแล้วเสีย
- “เสียเพิ่ม” ใช้กับวัตถุดิบเสียก่อนประกอบที่ยังไม่รวมในใช้ผลิต ต้องมีสาเหตุแยกรายการ
- ตัวอย่าง ผลิตดี 2 เสียหลังประกอบ 1 สูตรใช้ชิ้นส่วนอย่างละ 1: ใช้ผลิตอย่างละ 3 หากแผงฉีกก่อนประกอบอีก 1 ให้เสียเพิ่มแผง 1 รวมตัดแผง 4 และรับสินค้าดี 2

## ข้อมูลที่ยังต้องเติม

- สูตร 311 สูตรมีจำนวนฐาน 1 ทั้งหมด วัตถุดิบ 1,192 แถว: 1,189 แถวใช้ 1 และ 3 แถวใช้ 2 ไม่มีจำนวนใช้ติดลบหรือศูนย์ การตรวจนี้ยืนยันรูปแบบตัวเลข ไม่ได้ยืนยันสูตรทางโรงงานแทนผู้ใช้
- หน่วยสูตรต่างจากทะเบียน 102 แถว ให้ Admin ระบุอัตราก่อนบันทึกแผนที่ใช้รายการนั้น
- ข้อมูลต้นทางหลัก/รองว่าง 688 แถว เดิมตัวนำเข้ากำหนดเป็นหลักโดยปริยาย รอบนี้บังคับ Admin ระบุสำหรับใบงาน ไม่แก้ข้อมูลต้นทาง 688 แถวเป็นหลักหรือรองเอง
- 8 สูตรไม่มีวัตถุดิบยังคงปิดใช้งาน ต้องมีสูตรจริงก่อนเปิด
- ใบงานเดิม 3 ใบยังเป็น DRAFT ให้แก้ไขเลือก BOM ก่อนส่งงาน ไม่มีการผูกสูตรหรือแปลงหน่วยย้อนหลังอัตโนมัติ
- การปรับยอดสะสมอย่างเดียวถูกปิดสำหรับใบงานที่มีสูตร เพราะต้องกระทบทั้งวัตถุดิบและตำแหน่งสินค้าสำเร็จรูป การแก้รายงานที่ลงสต็อกแล้วต้องออกแบบรายการกลับและบันทึกใหม่แยกต่างหาก

## ฐานข้อมูลและความเข้ากันได้

เพิ่ม `production_material_plans`, `production_material_reservations`, `production_material_reports` พร้อม foreign key และ RLS ให้เฉพาะบทบาทเซิร์ฟเวอร์ `stockify_app` เก็บรายละเอียดรายงานแบบห้าม update/delete สำหรับบทบาทแอป

สูตรถูกสำเนาลงใบงาน จึงไม่เปลี่ยนตาม BOM ที่แก้ภายหลัง รองรับหน่วยสต็อกละเอียดถึง 0.001 ตามข้อจำกัดฐานข้อมูล แต่หน่วยนับเป็นชิ้นต้องเป็นจำนวนเต็ม จำนวนเป้าหมายและผลผลิตยังรับทศนิยมสูงสุด 2 ตำแหน่งตามระบบเดิม

เส้นทางใหม่ใช้ PostgreSQL ส่วนเส้นทาง Google Sheets เดิมยังใช้วิธีรับสินค้าสำเร็จรูปเดิม แก้การสร้าง stock summary ซ้ำเพื่อไม่ให้ยอด ledger ติดลบชั่วคราวจากการเบิกวัตถุดิบชน constraint ก่อนข้ามแถวที่มีอยู่ และย้าย Express status cache ออกจาก export ของ Route Handler เพื่อให้ Next.js ตรวจชนิดและ build ได้

ตรวจหลัง migration: สินค้า 3,008 รายการ, movement 2,358 รายการ, stock summary 3,993 แถว, ผลรวมจำนวน 7,106,401.6 เท่าเดิม ใบงาน 3 รายการ รายงาน 0 รายการ ตารางใหม่ทั้งหมดว่างและ RLS เปิดใช้

## แก้ข้อความส่งงานไม่สำเร็จ

ตรวจพบการกดส่งงาน `PRD-20261021-000001` ตอบ HTTP 400 เพราะฉบับร่างเดิมไม่มีแผน BOM โดยข้อความผิดพลาดเดิมแสดงด้านบนด้วย toast หายภายใน 4.5 วินาที ปรับให้ข้อผิดพลาดแสดงค้างใกล้ปุ่มยืนยันด้านล่าง พร้อมปุ่มเปิดแก้สูตรของใบงานที่ยังไม่ผูก BOM เพิ่มเลขใบงานในข้อความจากเซิร์ฟเวอร์ และแสดงเหตุผลที่บันทึกฟอร์มไม่ได้ใกล้ปุ่มบันทึก ทดสอบด้วยหน้าจำลองที่เรียก component หน้าจริง ยืนยันข้อความและการเปิดฟอร์มแก้ไขได้ โดยไม่ส่งผลิตจริง เพิ่มกรณีทดสอบฉบับร่างเก่าไม่มีสูตรให้ระบุเลขใบงานและยังคงสถานะเดิม

ตามคำสั่งเพิ่มเติม ปรับฟอร์มให้จับคู่ BOM อัตโนมัติทันทีที่เลือกสินค้า รวมกรณีหลายสูตรโดยเลือกสูตรแรกให้ดูและเปลี่ยนได้ ไม่ต้องเลือกสูตรเองก่อนเห็นวัตถุดิบ แยกการโหลดสูตรตามสินค้าออกจากการเปลี่ยนตัวเลือก จึงไม่โหลดใหม่และล้างรายการระหว่างสลับสูตรหรือกรอกอัตราแปลง ฉบับร่างเก่าที่ยังไม่มีแผนให้เปิด “ตรวจวัตถุดิบ” เพื่อโหลดสูตรอัตโนมัติ ตรวจข้อมูลที่ยังขาด แล้วบันทึกก่อนส่งผลิต ไม่สร้างอัตราแปลงหรือประเภทหลัก/รองขึ้นเอง

ตรวจรอบจับคู่สูตรอัตโนมัติ: TypeScript และ ESLint ผ่าน ทดสอบ BOM/workflow 2 ชุด 18 กรณีผ่าน ทดสอบ browser เลือกสินค้า AS12 จำลองแล้ววัตถุดิบ OS แสดงทันทีโดยไม่กดเลือกสูตร และสลับเป็น JHC แล้วแสดงเฉพาะวัตถุดิบ JHC สำเร็จ ภาพหลักฐาน `data/production-workflow-2026-10-21/auto-bom-proof.png`

## ขอบเขตวัตถุดิบเฉพาะโกดัง 2

ตามคำสั่งผู้ใช้ กำหนดแหล่งวัตถุดิบที่ใช้คำนวณกำลังผลิต ยอดพร้อมใช้ ยอดขาด จอง และตัดจริงเป็นโกดัง 2 เท่านั้น แม้ช่องคลังใน BOM ต้นทางหรือสำเนาสูตรของใบงานเก่าจะระบุคลังอื่น ไม่ตัดรายการวัตถุดิบออกจากสูตร ไม่รวมยอดคลังอื่น และไม่ย้ายสต็อกอัตโนมัติ หากโกดัง 2 ไม่พอต้องเติมของเข้าคลังก่อน สูตรต้นทางและจำนวนใช้เดิมไม่ถูกแก้ไข

ตรวจ TypeScript และ ESLint ผ่าน ทดสอบ workflow และ PostgreSQL storage รวม 2 ชุด 27 กรณีผ่าน รวมกรณีคลังอื่นมี 1,000 แต่โกดัง 2 มี 30 คำนวณจาก 30 เท่านั้น การจองและตัดจริงไม่แตะคลังอื่น และเมื่อโกดัง 2 ไม่เหลือวัตถุดิบหลัก ต้องแสดงผลิตได้ 0 และปฏิเสธส่งงานแม้คลังอื่นยังมีของ การทดสอบทั้งหมดใช้ฐานข้อมูลจำลอง

## ลดข้อความในหน้าผลิต

ตามคำขอผู้ใช้ ลบคำอธิบาย ขั้นตอน ตัวอย่างการกรอก และข้อความแนะนำออกจากฟอร์มผลิต วัตถุดิบ รายงานผล หน้ายืนยัน และท้ายสรุปผล เหลือชื่อช่องแบบสั้น ข้อมูลสินค้า/สูตร จำนวน สถานะ ปุ่ม และข้อผิดพลาดที่จำเป็น คงกติกาการคำนวณ การบันทึก และข้อความหมายเหตุที่ผู้ใช้กรอกเอง

## จำนวนผลิตได้ในช่องค้นหา

รายการค้นหาสินค้าแสดง “ผลิตได้ … หน่วย” ข้างบาร์โค้ด/SKU คำนวณจากวัตถุดิบหลักในโกดัง 2 หลังหักยอดจอง ใช้สูตรแรกเดียวกับสูตรที่ฟอร์มจับคู่อัตโนมัติ ไม่รวมจำนวนจากหลายสูตร และไม่จำกัดด้วยยอดวัตถุดิบรอง รายการที่หลัก/รองหรือหน่วยของตัวหลักยังไม่ยืนยันแสดง “ผลิตได้ —” แทนการเดาอัตราแปลง การแก้ใบงานไม่นับยอดจองของใบงานนั้นซ้ำ ใช้ API คำนวณแบบรวมเพื่อไม่ต้องเรียกแยกทุกสินค้า

ตรวจ TypeScript และ ESLint ผ่าน ทดสอบคำนวณและ workflow 2 ชุด 23 กรณีผ่าน ครอบคลุมหน่วยที่ยังไม่ยืนยัน ตัวหลักซ้ำ การจอง และหลายสูตรต่อสินค้า ตรวจฟอร์มจริงด้วยข้อมูลจำลองแสดง “ผลิตได้ 20 ชุด” ในรายการค้นหาแล้ว ภาพ `data/production-workflow-2026-10-21/search-capacity-proof.png`
